- [x] Guide can generate AI-drafted research problems and store them for students
- [x] AI evaluates proposals: novelty (arXiv TF-IDF), feasibility + clarity (LLM)

- [x] Human Gate 3 — guide ratifies viva with their own overall score; grade is written only via ratify endpoint
- [x] Multi-tenant isolation enforced throughout (tenant schema, no cross-tenant queries)
- [x] Audit log on every state-changing action (14 M07-specific AuditEventType entries)
- [x] All AI outputs advisory only; status never advances autonomously past EVALUATED

## Architecture decisions

### OQ-07: Real-time vs async viva
**Decision:** Async viva — student records responses within a configurable time window (default 72h).
**Rationale:** Avoids WebRTC/WebSocket complexity; recordings can be reviewed asynchronously; fits university workflow.

### M06 reuse strategy
`ai_scan.scan()` and `compute_plagiarism()` imported directly from M06 — never copied.
`document_eval.py` line 31–32: `from app.modules.m06_labs_evaluator.ai_scan import scan as ai_scan`

### DPDP Act 2023 compliance
`consent_recorded` boolean on VivaSession. `process_viva_session.py` skips ASR if `consent_recorded = False`.

### Human gate enforcement
All three gates enforced at API + service + repository levels:
- Gate 1: `ProblemService.guide_decide()` → only path to ACCEPTED/REJECTED
- Gate 2: `DocumentService.guide_review()` → only path to APPROVED
- Gate 3: `VivaService.ratify()` → only path to GUIDE_RATIFIED

AI Celery tasks set status = EVALUATED and write scores. Status never advances further without explicit human endpoint call.
